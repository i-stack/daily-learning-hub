IOS-D024

图片显示链路：从网络字节到屏幕纹理

渲染机制 · 2026-09-02 · Image I/O / CGImageSource / 图片解码 / Downsampling / 纹理上传 / 内存峰值
01 原文02 逐句白话03 核心思想04 关联知识05 现实映射06 今日思考07 知识验收08 掌握标准

打通压缩图片从网络 Data、格式解析、下采样与位图解码，到 CALayer 内容、纹理上传和 GPU 合成的完整链路。

01 原文

背景、API 与场景：网络返回的 JPEG、PNG、HEIF 或 WebP 数据是压缩文件字节，并不是可以直接显示的像素。常见入口包括 URLSession、Data、UIImage(data:)、CGImageSourceCreateWithData、CGImageSourceCreateImageAtIndex 与 CGImageSourceCreateThumbnailAtIndex。聊天流、瀑布流和相册最容易出现『下载已经结束，首次显示仍卡顿』，因为网络完成只代表压缩数据到达，格式解析、解码、颜色处理和纹理上传仍可能发生在后续显示链路。

02 逐句白话

运行机制：Network Data 先由 Image I/O 识别容器格式和元数据，再按目标尺寸生成 CGImage。压缩数据需要解码为像素缓冲区；以常见 8-bit RGBA 粗略估算，解码内存约为 pixelWidth × pixelHeight × 4 bytes，与 JPEG 文件只有几百 KB 并不矛盾。随后 UIImage/CGImage 成为 CALayer.contents 的图像内容，渲染系统准备可供 GPU 采样的纹理并在合成阶段显示。创建 UIImage 对象不应被等同于『全部显示成本已经支付』；实际时机受 API、缓存选项和渲染路径影响，应通过 Instruments 验证。

03 核心思想

底层原理：性能关键不是图片文件体积，而是解码后的像素数量、位图格式、同时存活的缓冲区数量与发生工作的线程。Image I/O 的 CGImageSource 管理输入数据和解码；CGImageSourceCreateThumbnailAtIndex 配合 kCGImageSourceThumbnailMaxPixelSize 可按展示尺寸下采样，避免先完整解码超大原图再缩小。kCGImageSourceShouldCacheImmediately 可控制在创建阶段执行解码缓存，使成本从首次显示时移到可控的后台阶段。颜色空间与 EXIF orientation 也属于正确显示的一部分。

04 关联知识

Apple 设计动机与架构：压缩格式节省网络和磁盘，位图适合 CPU 绘制与 GPU 采样，两种表示服务不同目标，因此必须经过转换。Image I/O 把格式识别、元数据、渐进加载、缩略图和解码统一在数据源抽象中；Core Graphics 提供 CGImage 像素图像；Core Animation 负责提交 Layer 状态；GPU 负责最终纹理采样与合成。工程架构应分开保存原始响应缓存、解码后内存缓存和屏幕目标尺寸，不能用一个『图片缓存』概念混为一谈。

05 现实映射

工程实战：一、从 Image View 的 point 尺寸乘以屏幕 scale 得到目标像素边长；二、后台用 CGImageSourceCreateThumbnailAtIndex 下采样并应用方向变换；三、用 NSCache 按解码成本而非文件字节数设置 cost；四、复用 Cell 时取消旧请求，并以稳定 messageID 校验异步回写；五、只在主线程更新 UIImageView/CALayer；六、用 signpost 标记下载、解析、下采样、主线程赋值与首次显示，再用 Time Profiler、Allocations 和 Animation Hitches 对照验证。

06 今日思考

常见坑与反思：把下载耗时当成图片总耗时；用原图像素解码后再靠 contentMode 缩小；只缓存压缩 Data，导致滚动时反复解码；只缓存 UIImage 却不设成本和淘汰策略；在主线程做大图解码；Cell 已复用仍回写旧图片；忽略 scale、色彩空间和方向；看到内存上涨就断言泄漏，而没有区分缓存、临时峰值和真正不可达对象。反思：当前列表里的每张图，实际展示像素与源文件像素相差多少？

08 掌握标准

一句话总结：图片性能的核心是让正确尺寸的像素在正确线程、正确时机被解码和缓存，而不是只追求更小的下载文件。掌握标准：60 分能区分压缩数据与解码位图并估算内存；80 分能实现后台下采样、取消和身份校验；100 分能设计分层图片管线，并用 signpost、Allocations 与 Hitches 证明首次显示卡顿和内存峰值已经下降。
