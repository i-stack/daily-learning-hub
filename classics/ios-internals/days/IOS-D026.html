网络缓存与连接复用：从 NSURLCache 到 HTTP 协商缓存

网络机制 · 2026-09-19 · URLCache / Cache-Control / ETag / 304 / 连接复用 / URLSessionTaskMetrics
01 背景与 API02 运行机制03 底层原理04 设计与取舍05 工程实战06 常见坑与反思07 知识验收08 掌握标准参考资料

分清响应缓存与连接复用，用 HTTP 响应头和 URLSessionTaskMetrics 验证数据、往返与建连成本究竟省在何处。

01 背景与 API

背景、API 与场景：图片、配置、详情页反复发起 GET。URLSessionConfiguration.urlCache 指定 URLCache，requestCachePolicy 规定缓存策略，默认 useProtocolCachePolicy 遵循协议语义。另一种复用是持久连接：即使请求实际到达服务器，URLSession 也可能沿用已有连接。响应缓存复用内容，连接复用节省建连成本；两者不可混同。

02 运行机制

运行机制：服务器用 Cache-Control、Expires、ETag、Last-Modified 等字段约束缓存。新鲜且允许复用的响应可直接使用；过期但有验证器时，客户端可带 If-None-Match 或 If-Modified-Since 请求验证。304 Not Modified 让客户端结合本地缓存内容使用；200 则可能带来新表示。是否缓存还取决于请求方法、策略、响应头与会话配置，不能见到 200 就断言内容已缓存。必须联网时，系统尝试复用合适的持久连接；代理、网络切换、空闲超时和协议协商都可能阻止复用。

03 底层原理

底层原理是两条独立轴：内容是新鲜命中、条件验证或完整下载；传输是无需联网、复用连接或新建连接。条件请求即使得到 304，仍有网络往返。200 请求也可能沿用连接。HTTP/2 可在一条 TCP 连接上多路复用，HTTP/3 则以 QUIC 承载多路流。用 URLSessionTaskTransactionMetrics 的 resourceFetchType、isReusedConnection、networkProtocolName 观察结果，而不是用总耗时猜测。

04 设计与取舍

Apple 的设计取舍：URL Loading System 将标准 HTTP 缓存和连接管理封装在会话中，让应用不必手写文件缓存和 socket 池。工程架构还需区分 HTTP 响应缓存、领域数据缓存和图片解码缓存：前者由协议与服务器控制有效性，中者由身份及业务版本控制，后者由目标像素和内存压力控制。不能用一个全局缓存开关替代三套契约。

05 工程实战

工程实战：一、测试服务分别返回 max-age、ETag 和 no-store，观测首次、有效期内和过期后的请求；二、明确配置 urlCache 与 requestCachePolicy，注意临时会话使用私有内存缓存，后台会话默认没有 URLCache；三、在 didFinishCollecting 收集 Task Metrics，记录 resourceFetchType、isReusedConnection、networkProtocolName 与阶段耗时；四、对登录态内容审查 Cache-Control、Vary 和身份边界，不在日志中记录 Token 或私有正文；五、为变更操作设计业务缓存失效；六、保持同一会话重复请求，分别验证内容命中率与连接复用率。

06 常见坑与反思

常见坑：以为设置缓存容量就强制缓存所有响应；把 304 当成零网络成本；把 reloadIgnoringLocalCacheData 当成清空所有缓存；忽略 no-store、Vary、身份隔离；认为 HTTP/2 必然沿用同一连接；频繁创建会话却期待稳定复用；业务手写缓存没有失效与淘汰规则。反思：现有“缓存优化”究竟减少了响应字节、网络往返，还是连接建立？

07 知识验收

  1. 新鲜命中、条件验证、完整下载分别可能产生哪些网络行为？
  2. ETag/If-None-Match 与 Last-Modified/If-Modified-Since 如何形成条件请求？304 后为何仍需本地表示数据？
  3. URLCache、领域缓存和解码图片缓存各由谁决定有效性？
  4. 为什么收到 200 不能证明没有复用连接？
  5. 如何用 resourceFetchType 与 isReusedConnection 设计可证伪实验？
  6. 面试题：说明响应缓存与连接复用的区别，并解释何种情况无需实际联网。

08 掌握标准

一句话总结：缓存回答“内容能否复用”，连接复用回答“联网时能否沿用传输通道”，必须分别设计、测量与归因。掌握标准：60 分能解释 Cache-Control、ETag、304 与持久连接；80 分能用响应头和 Task Metrics 复现实验；100 分能为登录态数据建立安全的缓存边界、失效策略和可观测指标。
